1 Why Does MPI Even Exist?

Your laptop has 1 brain (CPU). Supercomputers have thousands. How do you make them work together on ONE big problem?

🍕 Analogy: The Pizza Factory
You need to make 10,000 pizzas. One chef = 10,000 hours. 100 chefs = 100 hours — IF they can coordinate. MPI is the walkie-talkie system they use to coordinate. No walkie-talkie = chaos, pizzas duplicated or missed.
❌
Shared MemoryLike all chefs sharing one kitchen counter. They step on each other. Works for 2-4 chefs, fails for 1000.
✅
Message Passing (MPI)Each chef has his OWN kitchen. They send ingredients via envelopes. Works for 10,000 chefs.

→ That's why your PDF says "Local address space per node — NO physically shared memory — Processes communicate by explicit send/receive pairs". It's just separate kitchens + envelopes.

2 The One Pattern That Rules Them All: SPMD

MOST IMPORTANT Single Program, Multiple Data

You write ONE program. The computer makes P photocopies and runs the same code on every processor. The trick: each copy checks its ID number to decide what to do.

// You write this ONCE
if (rank == 0) { // I'm the boss
  print("I will distribute work");
} else { // I'm a worker
  print("I will work on my chunk");
}
🏫 Analogy: Exam Papers
Teacher gives the exact same exam to 30 students. But question 1 says: "If your student ID is even, solve problem A, if odd, solve problem B". Same paper, different work based on ID. That's SPMD. Rank = your student ID (0 to P-1).

Your PDF says: "Use the rank … an ID ranging from 0 to (P-1) … to select between a set of tasks" — that's literally this.

3 The 4 Magical Lines (90% of MPI is this)

Every MPI program looks identical. Learn this skeleton and you can read any MPI code:

#include <mpi.h> // 0. Must include this, like #include <stdio.h>

int main(int argc, char *argv[]){
  int rank, size;

  MPI_Init(&argc,&argv); // 1. START MPI — wakes up all processes
  MPI_Comm_rank(MPI_COMM_WORLD, &rank); // 2. WHO AM I? (0,1,2...)
  MPI_Comm_size(MPI_COMM_WORLD, &size); // 3. HOW MANY ARE WE?

  printf("Hello, I'm %d of %d\n", rank, size); // YOUR WORK HERE

  MPI_Finalize(); // 4. STOP MPI — no MPI calls after this!
  return 0;
}
MPI_COMM_WORLD
Sounds scary, just means "the group chat that includes EVERYONE". There can be smaller groups, but 99% of time you use WORLD.
rank & size
If you run mpirun -np 4 ./hello, size=4, ranks are 0,1,2,3. Rank 0 is often "the boss".

5 Point-to-Point: The Envelope (MPI_Send / Recv)

Every message is an envelope with 5 things written on it:

📦 buf what's inside
🔢 count how many items
🏷️ datatype MPI_INT, MPI_CHAR, MPI_DOUBLE...
👤 dest/source who is it for/from
🔖 tag like subject line (0-32767)
// Sender (Rank 0)
char msg[20] = "Hello, world";
MPI_Send(msg, 13, MPI_CHAR, 1, 100, MPI_COMM_WORLD);
// | | | | | |
// buf count datatype dest tag communicator

// Receiver (Rank 1)
MPI_Recv(msg, 13, MPI_CHAR, 0, 100, MPI_COMM_WORLD, &status);
// source tag
✅ Tag trick
Tags let you have different conversations. Rank 0 can send tag=100 for "data" and tag=200 for "done". Receiver can filter. Use MPI_ANY_TAG or MPI_ANY_SOURCE if you don't care.
💀 Deadlock danger
If Rank 0 does Send to 1 and Rank 1 does Send to 0 at SAME time, both wait forever. Solution: use MPI_Sendrecv — it sends AND receives at once, no deadlock.
📖 Your PDF example (page 13 simplified):
Rank 0 does a loop: for(i=1; i<size; i++) MPI_Send(... to i) — boss sends "Hello" to everyone.
Everyone else (rank !=0) does one MPI_Recv(from 0) and prints. Result you saw: every node prints "Hello, world". That's a manual broadcast — but there's an easier way…

6 Collectives: The 6 Superpowers (Memorize These Pictures!)

Collectives are why MPI is easy. Instead of 100 Send/Recv, you call ONE line and everyone is coordinated.

🚧
BARRIER
MPI_Barrier(world)
Everyone waits at a wall until ALL arrive. No one passes early. Like "wait for all friends before entering cinema".
● ● ● ● → ▮ → ● ● ● ●
📢
BROADCAST (Bcast)
MPI_Bcast(buf, count, type, root, world)
One → All. Root has data, everyone gets a copy. Like teacher photocopying one handout for whole class.
P0:[A] → P0[A] P1[A] P2[A] P3[A]
🃏
SCATTER
MPI_Scatter(sendbuf, ..., recvbuf, ..., root, world)
One → All, but different piece each. Root deals cards: P0 gets A1, P1 gets A2... Like cutting a cake.
P0:[A,B,C,D] → P0[A] P1[B] P2[C] P3[D]
🧲
GATHER
MPI_Gather(sendbuf,..., recvbuf,..., root, world)
All → One. Reverse of Scatter. Everyone sends their piece to root who assembles full array in rank order.
P0[a] P1[b] P2[c] P3[d] → P0:[a,b,c,d]
🧲🧲
ALLGATHER
MPI_Allgather(...)
All → All. Like Gather but everyone ends up with the full array. No root.
P0[a] P1[b] → Everyone[a,b]
➕
REDUCE / ALLREDUCE
MPI_Reduce(send, recv, 1, type, MPI_SUM, root, world)
All → One (or All) with MATH. Everyone has a number, combine with + * max etc. Root gets answer. Allreduce = everyone gets answer.
2, 4, 6, 8 → P0: 20 (sum)
🎯 How to remember:
Bcast = photocopier  |  Scatter = dealing cards  |  Gather = collecting homework  |  Reduce = calculator that sums everyone's answer

7 Real Example: Compute Average of 100 Numbers Together

Your PDF does this on page 20-21. Here it is in human:

1
Root (P0) creates 100 random numbers [0.2, 0.8, 0.5, ...]
2
SCATTER them: 4 processes → each gets 25 numbers. MPI_Scatter(100 numbers, 25 each, root=0)
P0: 25 nums P1: 25 nums P2: 25 nums P3: 25 nums
3
Each computes local average — no communication, just local math
P0 avg=0.51, P1 avg=0.53, P2 avg=0.49, P3 avg=0.52
4
GATHER (or REDUCE): Send locals back to root
MPI_Gather(local_avg → root) or better MPI_Reduce(local_sum with MPI_SUM)
5
Root computes final average = sum of all / 100 → 0.518!
// PSEUDOCODE - the whole logic in 5 lines
// On root: generate 100 numbers
MPI_Scatter(all_numbers, 25, MPI_FLOAT, my_25, 25, MPI_FLOAT, 0, world);
my_avg = average(my_25); // everyone does this locally
MPI_Gather(&my_avg, 1, MPI_FLOAT, all_avgs, 1, MPI_FLOAT, 0, world);
if(rank==0) final = average(all_avgs);
💡 Pro version (PDF page 25): Instead of Gather + manual average, just do MPI_Reduce(&local_sum, &global_sum, 1, MPI_FLOAT, MPI_SUM, 0, world) — it sums everything in ONE step! Then divide by 100. Cleaner!
Same idea with Matrix × Vector (PDF page 21):
Matrix A is 100×100. You have 4 tasks. Each task gets 25 rows of A (Scatter). Vector B (length 100) is Broadcast to everyone. Each computes 25 elements of C. Then Gather cpart (25) from each into ctotal (100) on root. Done!

8 3 Traps That Kill Beginners (and How to Survive)

1. Deadlock — Two people waiting for each other to speak first
If you do: Rank0: Send to 1 → Recv from 1 and Rank1: Send to 0 → Recv from 0, both Sends block forever. Fix: Use MPI_Sendrecv (does both at once) or make one rank Send first, the other Recv first.
2. Count/Type Mismatch — Envelope says 10 ints but receiver expects 10 chars
Sender: MPI_Send(buf, 10, MPI_INT...) Receiver: MPI_Recv(buf, 10, MPI_FLOAT...) → CRASH or garbage. Fix: Always match count and datatype. For Bcast/Reduce, EVERY rank must use SAME count/type.
3. Forgetting that Collectives are SYNCHRONIZED
All ranks must call MPI_Bcast / MPI_Barrier / MPI_Reduce. If rank 2 skips it, everyone else hangs forever waiting for rank 2. Fix: No if-statements that make only some ranks call a collective (unless intentional with separate communicators).
